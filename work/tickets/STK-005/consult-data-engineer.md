## Findings

### Repo state
- apps/worker is a scaffold (src/index.ts only logs). Its package.json depends only on @stoktok/core. It has no @stoktok/db dependency, no vitest, no test script and no env loading, so the ticket must add these.
- prices_daily has primary key (symbol, trade_date). Columns open/high/low/close are integer, with a CHECK that low <= open/close <= high. Volume is bigint >= 0. foreign_net is nullable and in VND. source and fetched_at are NOT NULL. This suits an idempotent upsert.
- data_gaps has NO unique constraint. Its columns are symbol (nullable), data_type, from_ts, to_ts, detected_at, source, fetched_at and resolved_at, with an index on (symbol, from_ts) only. Re-running gap detection would insert duplicates. The gap writer needs select-then-insert dedupe on (symbol, data_type, from_ts, to_ts) where resolved_at is null, or a small migration adding a partial unique index. A migration crosses into the db area, but the ticket lists db, so it is allowed. It would be the cleaner option.
- packages/db has prices-daily.ts with only getLatestCloses (a read). There is no upsert, no range read and no gap repo yet. STK-005 adds `upsertDailyPrices`, `listPriceDates(symbol, from, to)` and a data-gaps repo. The existing pattern is Db + unwrap + mapRow + DataError. The fake client already supports `upsert`, `gte`, `lte`, `eq` and `select`, so repo tests need no changes to the fake.
- listWatchlist exists in packages/db. I did not find a held-symbols repo. Held symbols come from the ledger (packages/db/src/ledger.ts plus core build-ledger), so the job should reuse that.
- core calendar.ts has isTradingDay(date, holidays), addTradingDays, previousTradingDay, vnDateOf and vnMinutesOf. It has no "list trading days in a range" helper. Add `tradingDaysBetween(from, to, holidays)` to core with unit tests (R8).
- portfolio/freshness.ts has expectedPriceDate(now, holidays, cutoffMinutesVn). The job should use it to pick the target end date, so the job and the dashboard agree on "fresh". The cutoff must come from config (R5).

## Recommendations

1. Primary source (AC1, spec §9 Q4). SSI FastConnect Data via an `SsiFastConnectPriceSource`, if Ming registers (an SSI account and consumerID/secret, put in `.env.local`). Rationale: official, documented, with explicit credentials, which is the best legal posture. This is the only option that does not depend on tolerance of an undocumented endpoint.
2. Fallback source. TCBS public bars (Ming is a TCBS customer, and it is the lowest-friction option), with VNDirect dchart as an alternative. Mark both as "unofficial, tolerated, may break" in a doc comment and in the ADR. Enable the unofficial fallback only by config, with a conservative rate (below).
3. If Ming does not want to register, the planner may implement the interface plus ONE unofficial adapter (TCBS or VNDirect) against recorded fixtures. Tests make no live calls, so this works without a decision. Record Ming's explicit acceptance of the unofficial-source risk in the ticket and the ADR. Per the ticket Notes, return BLOCKED for the source decision if Ming wants a clear licence before any live run. My suggestion is to split the ticket into (a) interface, job, repos and gaps, which are unblocked, and (b) the live adapter, which waits on Ming.
4. `PriceSource` contract. `fetchDaily(symbol, fromDate, toDate): Promise<DailyBar[]>`, with `readonly name`. `DailyBar` has integer VND open/high/low/close, volume, optional foreignNet, and tradeDate as 'YYYY-MM-DD'. The adapter returns `source` and the job stamps a single `fetched_at` per run (R4). Put a pure `normalizeBar` in core or in the adapter. It rejects non-finite, negative, non-integer-after-conversion, low > high, or open/close outside [low, high] (this mirrors the DB CHECK), and returns a rejection list, never a stored row (AC3). Log rejected counts per symbol.
5. Unit conversion (R2/AC3). Convert at the adapter boundary only. If the source quotes thousand VND, use `Math.round(x * 1000)` (or decimal-string arithmetic) and then assert `Number.isSafeInteger`. Reject any bar that is not a multiple of 1 VND after conversion tolerance. Each adapter declares its unit explicitly in one constant, and its fixtures prove it (for example, a VNM close of about 60000-90000 VND is plausible, while 60-90 means the unit is wrong). Also add a sanity check that rejects a bar whose close differs from the previous stored close by more than 3x the exchange limit, which catches unit errors.
6. Adjusted versus raw. Store RAW (unadjusted) prices. The ledger and cost basis rely on corporate actions entered manually, and adjusted series would double-count them. Each adapter must state which it returns. If a source only provides adjusted data, flag it in the ADR. Signals (MA, 50/200-day) may later need adjusted series, which is a separate decision. Do not add a column in this ticket (R7); put it in follow-ups.
7. Symbol scope. Sync `watchlist ∪ held symbols` (held means net quantity > 0 from the ledger, via existing core/db helpers), deduped and uppercased, sorted for deterministic ordering. Include symbols sold within the last N days only if cheap, otherwise skip. Document that the AC wording "watchlist symbols" is satisfied by the union. Flag it in the plan as a clarification.
8. Date range per symbol. `from` = (latest stored trade_date for the symbol) + 1 trading day, or a configurable lookback (for example 10 trading days) on first run. `to` = expectedPriceDate(now, holidays, cutoff). Always re-fetch the last 1-3 trading days (overlap window) so late corrections are picked up. The upsert makes this safe.
9. Idempotent upsert (AC2). `db.from('prices_daily').upsert(rows, { onConflict: 'symbol,trade_date' })` in chunks (about 500 rows). "Re-running changes nothing" in strict terms: `fetched_at` will change on a re-run. Two options. (a) Accept that `fetched_at` records the latest fetch, and test that the rows are identical apart from fetched_at and that the row count is unchanged. (b) Only write when OHLCV differs. Prefer (a) for simplicity. State the choice in the plan, and note that AC2 "changes nothing" should be read as "no duplicates and no data change".
10. Gap detection (AC4). For each symbol, compute expected = tradingDaysBetween(max(first held/watch date or earliest stored date or lookback start, ...), to, holidays), then missing = expected minus stored dates, after the fetch. Collapse consecutive missing trading days into ranges. Write to data_gaps with data_type 'prices_daily', symbol, from_ts and to_ts (the start of the first day and end of the last day in Vietnam time, converted to UTC), source = the source name, fetched_at = the run time. Weekends and listed holidays are never gaps (core's isTradingDay). A symbol that returns nothing for a day when other symbols did is a symbol-level gap, whereas an empty response for all symbols is a market-wide gap (symbol NULL). Be careful: a suspended or newly listed symbol also has "missing" days. Never start the expected range before the symbol's first stored date or its first ledger or watchlist date. Mark gaps `resolved_at` when the data later arrives (a resolve step in the same job). Dedupe, as noted above.
11. Holidays and config (R5). Add a `MARKET_HOLIDAYS` config (a list of 'YYYY-MM-DD', loaded from an env var or a JSON file under apps/worker/config) plus an EOD cutoff (minutes after midnight VN time, default 15:15 for HOSE/HNX, e.g. 16:00 to be safe) and a request-delay setting. Do not hard-code them. The holiday list is the temporary place until the later holiday ticket. Document that a missing holiday would create false gaps until the list is updated, and that these are self-healing (resolved_at is set when data arrives, or the day stays a gap if the exchange really was closed, so the list needs maintenance). Put the 2026-2027 Vietnamese holidays (Tet, Hung Kings, 30/4, 1/5, 2/9) in a doc as a starting point, but verify against official HOSE announcements.
12. Fixtures and tests (AC5). Put recorded JSON responses in apps/worker/test/fixtures/<source>/ (success, empty, a malformed bar, unit sample). Tests inject a `fetch` function into the adapter (constructor argument `fetchImpl = globalThis.fetch`). Never touch global fetch. Add a guard test or a vitest setup that stubs `globalThis.fetch` to throw, so any accidental live call fails the test. Capture the fixtures once manually (curl) and commit them with the capture date and URL in a comment or README. If the live capture is not possible for the implementer, hand-write the fixture from the documented shape and mark it "synthetic, unverified against live" in the README (do not claim it is recorded). Test the job with the createFake db and a fake PriceSource. Cover: idempotent re-run, a rejected bar, a gap range across a weekend and a holiday, a symbol with no data, the union of symbols, and a source error for one symbol not stopping the others.
13. Running the job (AC6). Add `apps/worker/src/jobs/sync-eod-prices.ts`, exporting `runEodSync(deps)`, and a CLI entry `apps/worker/src/cli.ts` taking a job name (`pnpm --filter @stoktok/worker run job eod-prices`, and a root alias `pnpm worker:eod`). Use `tsx` in dev and the built `dist` in the container. Load env with `process.env` (Node 20+ `--env-file=.env.local` works, so no dotenv). Exit non-zero on a failed run and print a one-line JSON summary (symbols, rows upserted, rejected, gaps written). Add a `--dry-run` flag that fetches and validates without writing.
14. Cron wiring, minimal. Preferred: a documented host crontab or a compose one-shot, for example `30 16 * * 1-5 cd /path && docker compose run --rm worker node dist/cli.js eod-prices` (the TZ must be Asia/Ho_Chi_Minh). The cron runs on weekdays only, and the job itself skips non-trading days or exits quickly. Do not build a scheduler framework in this ticket (R7). Add one retry run later in the evening (for example 19:00) because the PC may have been asleep at 16:30, and rely on gap detection for catch-up. Document in the ticket that the PC being off is covered by the overlap window plus gap detection.
15. Rate limits and retries. Process symbols sequentially or with concurrency 1-2, with a configurable delay (for example 300-500 ms between requests, higher for unofficial endpoints). A request timeout of 10-15 s via AbortSignal.timeout. Retry only on network errors, 429 and 5xx, up to 3 attempts with exponential backoff and jitter (1 s, 2 s, 4 s), and honor `Retry-After`. Do not retry 4xx other than 429 (a 401/403 on SSI means a bad token, so fail the whole run fast). Per-symbol failures are isolated and counted. If any symbol fails, the job exits non-zero after processing the rest. A circuit breaker: stop after N consecutive failures (for example 5), since that means the source is down. Never retry inside the adapter in a way that hides the failure: log each retry. Use a descriptive User-Agent identifying personal use, and no browser impersonation or header spoofing. Do not log secrets (SSI consumerSecret and token).
16. Provenance and R3. The worker uses the service role key from env via createServiceClient, never imported by web code. Keep `source` as a short stable identifier ('ssi-fastconnect', 'tcbs-public', 'vndirect-dchart').
17. Place the ADR in docs or the ticket folder: the chosen source, evidence of the terms check (URLs and date), and who accepted the risk.

## Risks
- Legal or ToS: unofficial endpoints (TCBS, VNDirect) are not licensed for automated access as far as I could determine. They could block or change at any time. Personal low-volume use (a few dozen requests per day) is low risk in practice, but it is not a clear permission.
- Wrong units (thousand VND versus VND) would silently corrupt every P&L number (R2). Mitigate with the explicit unit constant, fixture-proven tests and the jump sanity check.
- Adjusted prices mixed with raw ones would double-adjust cost basis. Mitigate by declaring raw per adapter.
- False gaps from an incomplete holiday list. Duplicate gap rows because data_gaps has no unique key.
- Suspended or newly listed symbols produce persistent "gaps" unless the range start is bounded.
- The worker has no test runner or db dependency yet, so scaffolding work is part of this ticket and may inflate its size.
- fetched_at changes on every run, so "re-running changes nothing" needs the clarification above.
- Fixtures could be synthetic rather than recorded if live capture is impossible, which would hide format drift. Label them honestly.
- vnstock Gen 5 is closed and precompiled and needs registration. Depending on it would conflict with the TypeScript stack, and the stack must not change without Ming's decision.
