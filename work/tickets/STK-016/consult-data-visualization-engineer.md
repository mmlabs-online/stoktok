# consult-data-visualization-engineer — STK-016

## Findings

- `/symbols/[symbol]/page.tsx` is a stub. It normalizes the symbol with `normalizeSymbol` and calls `notFound()`. It shows an EmptyState. Keep that normalize/notFound front half.
- Reusable pieces already exist in `apps/web/components`: `PriceChange`, `MoneyText`, `DataFreshnessBadge`, `LotStatusBadge`, `SymbolLink`, `StatCard`, `EmptyState`, `DisclaimerNote`, `TONE_STYLES` in `tone.ts`, `components/transactions/transaction-list.tsx`, and `components/portfolio/holdings-table.tsx`.
- `price-board.tsx` has a private `LimitValue` (ref/ceiling/floor with label, glyph, color and `sr-only` text) and a private `Close` (tone, tag, `sr-only`). The header needs both. Export or lift them instead of copying.
- `DataFreshnessBadge` takes `fresh: boolean | null`. The caller decides freshness. `buildPriceBoardRow` (core) already returns tone, ref/ceiling/floor, `status` and `tradeDate`.
- The loader pattern is `server/watchlist/load-watchlist.ts`, which reads through `server/db` and delegates all math to core. Its header comment says to add `requireUser()` later. STK-016 should follow it with `server/symbols/load-symbol.ts`. `db.ts` currently shows only `getDb`, so I didn't confirm the other accessors (e.g. `getRecentCloses`) are exported there.
- Core signals (`packages/core/src/signals/types.ts`):
  - `SignalResult` carries `status` ('ok' or 'suppressed'), `label` (bullish/bearish/neutral, or null), `value`, `dataFresh`, `reasons: ReasonCode[]` and `inputs`.
  - Data reasons: `price_missing`, `price_stale`, `insufficient_history`, `price_gap`, `price_gap_recorded`, `financials_*`, `sector_missing`.
  - Rule reasons: `eps_basis_unverified`, `eps_non_positive`, `bvps_non_positive`, `peers_insufficient`, `value_out_of_range`.
  - `SnapshotRef` carries `ref`, `source`, `fetchedAt`, `fromTs` and `toTs`, so R9 citations are available.
  - `GapRef` has `fromTs` and `toTs`, so chart gaps can come from the same data.
- `apps/web/test/no-calc-in-ui.test.ts` scans every `.tsx` under `components/` and `app/`. It forbids `reduce(`, `.toFixed(`, `Math.`, `parseInt/Float`, `*100`, `/100`, `/1000`, `Date.now()` and `new Date(`. SVG chart code is therefore constrained: scale math cannot live in a `.tsx` file.
- No chart library is installed (no recharts or d3 in any `package.json`). The brief says recharts, but CLAUDE.md says not to change the stack without Ming's decision. The brief only describes the UI. A new dependency is a Ming call.

## Recommendations

**1. Chart rendering (AC2).** Render SVG ourselves, with no library.
- The data is small: at most about 250 daily bars for 1N (1 year), so SVG is well within budget.
- Recharts adds roughly 100 KB or more, and its Line connects across missing points by default. Honest gaps would mean fighting it, and the library gives us no help with them.
- Put the geometry in a pure module, `packages/core/src/market/chart-series.ts` or `apps/web/lib/chart-geometry.ts`. A `.ts` file is not scanned by the R1 test, but R1 is about financial calculation, so I'd prefer core with unit tests.
- Inputs: bars, gaps, range, width and height. Outputs: path segments, volume bar rects, y ticks, gap bands and an x-axis label list.
- The `.tsx` component only maps those outputs to `<path>`, `<rect>` and `<text>`.
- Range slicing (1T/3T/6T/1N = 1/3/6/12 months) is done server-side. The page passes the bars for all ranges, or uses `?range=` as a search param. I prefer `?range=` with plain links, so tabs work without JS and are server-rendered. Load only that range's bars.
- Fall back to recharts only if Ming wants tooltips and zoom in v1. It is not needed for this ticket.

**2. Gap honesty.**
- Emit one `<path>` per contiguous run of bars. Never connect across a gap.
- Draw each `data_gaps` interval as a hatched band spanning the x-range. The hatch is a pattern, not a color-only cue. Label it "Thiếu dữ liệu dd/mm–dd/mm".
- A missing day with no recorded gap is still not interpolated. A normal non-trading day (holiday or weekend) is not a gap. Use the core holiday calendar to tell the two apart, not the UI.
- Use a categorical (trading-day) x-axis so weekends don't create false gaps.
- Volume bars sit in a lower panel on a zero baseline. The price axis is a line chart, so a non-zero baseline is fine, but label the min and max.
- Add a single line colored by neutral foreground. Do not color a daily close up or down. Up/down colors belong only to header change values.
- If the corporate-action `exDates` are used, adjusted vs raw prices must be stated. Check what `buildPriceBoardRow` does with `exDates` before charting raw closes across an ex-date.

**3. Accessibility.**
- Wrap the chart in `<figure>` with `role="img"` and an `aria-label` summary generated by the server: range, first and last close, high and low, gap count.
- Add a `<details>` "Xem dữ liệu dạng bảng" table fallback (date, close, volume, gaps listed).
- Range tabs are links with `aria-current="page"`, not a hand-rolled ARIA tablist.
- Rely on the light/dark tokens already covered by `contrast.test.ts`. The chart line and axis colors must use those tokens.

**4. VN price colors.**
- Use `TONE_STYLES` (glyph, tag and `sr-only` label, so color is never the only carrier).
- Ceiling is purple and floor is cyan. Up/down is green/red, and CLAUDE.md fixes those colors. Keep ref/ceiling/floor glyph-and-label (Trần/Sàn). Running the red/green pair through a CVD check is still advisable. The glyphs ▲ ▼ ■ already cover it.

**5. Layout.**
- Mobile (375px), single column in this order:
  1. Header, sticky optional. Symbol and exchange on line 1, big price with PriceChange on line 2, then a 3-up ref/ceiling/floor grid, then volume and freshness.
  2. Chart. Full-bleed, about 220 px high, with a `viewBox` and `width: 100%`. The range tabs form a 4-button row of at least 44px targets.
  3. Position card as a 2-column `StatCard` grid.
  4. Lots as stacked cards (or horizontally scrollable table). Check how `holdings-table` handles narrow screens and follow it.
  5. Signals.
  6. Transactions, compact, with a "Xem sổ giao dịch" link.
  7. `DisclaimerNote`.
- Desktop: a two-column grid. Chart and signals on the left, Position and Lots on the right. Transactions go full width underneath.
- Don't show the position and lots card at all when the symbol isn't held (the brief says "if held"). The header's watch toggle can come from the existing watchlist actions. The AC doesn't list it. Treat it as optional (see open questions).

**6. Signals (AC4).**
- Reuse the Prompt 4 structure and only the medium-term list. Short-term is out of scope per the AC, so no tabs.
- Per signal row:
  - Rule name, via a core or config label map. Don't hard-code it in the UI (R5).
  - A direction badge with glyph + text ("Tích cực" / "Tiêu cực" / "Trung lập"), described as a direction and never an action (R9, R10).
  - The value with its unit, formatted by core.
  - The signal date and freshness.
  - Inputs in a `<details>` listing each `SnapshotRef`: ref, source, fetchedAt, and fromTs–toTs. This is the R9/R4 citation.
- Suppressed (`status: 'suppressed'`) rows:
  - Show no direction and no value.
  - Show a muted row with "Tạm ẩn" and the reason(s) in Vietnamese, from a single `REASON_LABELS: Record<ReasonCode, string>` that is exhaustive via `satisfies` so a new reason breaks the build.
  - Data reasons get the warning style (like `DataFreshnessBadge`). Rule reasons (`eps_non_positive` and so on) get a neutral style, because that's "rule not applicable", not stale data.
  - Show the gap interval when the reason is `price_gap_recorded`.
- If every signal is suppressed for a data reason, show the Prompt 4 notice "Tín hiệu tạm ẩn do dữ liệu chưa cập nhật" once, with the individual reasons below it.
- If there are no stored signals, show an EmptyState. This is different from suppression.
- Always show the `DisclaimerNote` below.

**7. Data loading.** Create `server/symbols/load-symbol.ts`:
- Call `buildLedger`, then pick this symbol's holding and lots from core.
- Call `buildPriceBoardRow`, plus bar and gap queries and stored signal reads.
- The loader returns a flat view model that is ready to render.
- No auth code (R6 suspended). Add a comment like the watchlist loader's.
- Load in the server component only (R3).
- Unknown symbol: `notFound()` when the symbol is neither in the ledger, the watchlist, nor the stored prices. Decide which of those counts as "known".
- Tests: loader (as in `load-watchlist.test.ts`), chart geometry (gap splitting, ranges, empty/one-bar input), `REASON_LABELS` completeness, and component render tests like `components.test.tsx`.

## Risks

- A chart library added without Ming's decision breaks the "do not change stack" rule. Recharts' default line connects gaps, which would violate R4.
- The R1 scan could flag SVG code. Keep every calculation in `.ts` and out of components. Even `y + 4` for a label offset is fine, but `* 100` and `/ 100` (like percentage widths) are forbidden, so don't use percentage math.
- Adjusted vs unadjusted closes across ex-dates could show a fake cliff. This needs a check against how the stored closes are adjusted.
- STK-015 (signals) must be finished. Its stored-signal read API does not appear to exist in `server/db.ts` yet, so the loader may depend on an accessor STK-015 provides.
- With no signals available, a lot of this ticket is blocked on that dependency.
- Without auth, this page exposes portfolio data. That is already noted for STK-018.
- Long ranges on small screens: 250 bars in a 343px chart is under 2px per bar. Volume bars need a minimum width. Consider weekly aggregation of volume for 1N only if it becomes unreadable, and do it in core with an explicit label.
